# JOD tang
บอทจดเงินบน LINE ที่คุยภาษาคนได้ แต่ไม่ปล่อยให้ AI แตะเงินของผู้ใช้

1. โปรเจคนี้คืออะไร (อธิบายแบบ 30 วินาที)
ผู้ใช้พิมพ์ในแชท LINE ว่า "กาแฟ 80" → ระบบบันทึกรายจ่ายให้ทันที ถามว่า "สรุปเดือนนี้" → ได้การ์ดสรุปรายรับ-รายจ่าย ส่งรูปสลิปมา → AI อ่านยอดให้ แต่ ต้องกดยืนยันก่อนเสมอ

หัวใจของโปรเจค: AI เป็นแค่ "ล่ามแปลภาษา" ไม่ใช่ "นักบัญชี" — AI มีหน้าที่เดาว่าผู้ใช้อยากทำอะไรเท่านั้น ส่วนการคำนวณเงินและการบันทึกลงฐานข้อมูล โค้ดเราทำเองทั้งหมด

2. กฎเหล็ก 7 ข้อ (ต้องจำให้ได้ก่อนเขียนโค้ด)

#	กฎ	แปลเป็นภาษาคน
G1	AI ห้ามคำนวณเงิน	AI ดึงได้แค่ตัวเลขที่ผู้ใช้พิมพ์มา ห้ามบวกลบเอง ห้ามเดา
G2	AI ห้ามเขียน DB ตรง	ทุกครั้งที่ AI จะบันทึกอะไร ต้องเข้า pending_actions แล้วรอผู้ใช้กดปุ่ม
G3	เงินเป็นสตางค์ (integer)	ห้ามใช้ float เด็ดขาด 0.1 + 0.2 ต้องได้ 0.30 เป๊ะ และเงินติดลบไม่ได้
G4	ปิด AI แล้วแอปต้องยังใช้ได้	ตั้ง AI_ENABLED=false แล้วฟังก์ชันหลักต้องทำงานครบ
G5	ไม่ส่งข้อมูลส่วนตัวให้ AI	เลขบัญชี/บัตร/เบอร์ ถูกปิดก่อนส่ง + ประวัติแชทไม่เกิน 3 turn
G6	user_id มาจากลายเซ็นเท่านั้น	ห้ามเชื่อ user_id ที่ส่งมาจาก client เด็ดขาด
G7	transfer ไม่นับเป็นรายรับ/รายจ่าย	โอนเงินระหว่างบัญชีตัวเองไม่ใช่รายจ่าย
⚠️ PR ที่ผิดกฎข้อใดข้อหนึ่ง = ไม่ merge ไม่ว่าโค้ดจะสวยแค่ไหน

3. ระบบทำงานยังไง (ภาพรวม)


ผู้ใช้พิมพ์ใน LINE
      ↓
[webhook] ตรวจลายเซ็น → ตอบ 200 ทันที (< 1 วิ) → ประมวลผลเบื้องหลัง
      ↓
[คำสั่งตายตัว?]  "สรุปเดือนนี้" → ตอบเลย ไม่แตะ AI
      ↓
[Router 4 ชั้น]
   L1  regex จับได้เลย        → "กาแฟ 80"        → บันทึกทันที ✅
   L2  พจนานุกรมกลาง          → "ค่าไฟ 900"      → บันทึกทันที ✅
   L3  พจนานุกรมส่วนตัว        → "ร้านป้าแดง 50"  → บันทึกทันที ✅
   L4  ส่ง Gemini (ทางสุดท้าย) → "เมื่อวานกินข้าวกับเพื่อนหมดไปสามร้อย"
                                  ↓
                          เข้า pending → ผู้ใช้กดยืนยัน → ถึงจะบันทึก (G2)
ทำไมต้อง 4 ชั้น? — ประหยัดเงิน ตอบเร็วกว่า และถ้า Gemini ล่มก็ยังใช้งานได้ (G4)

> ⚠️ สถานะจริงตอนนี้: **L2/L3 ยังไม่ได้เขียน** (`services/keyword.service.ts` ยังว่าง และตาราง `user_keyword_map` ยังไม่มีโค้ดหรือ trigger แตะ)
> ข้อความที่ regex อ่านได้จะจับคู่กับหมวดที่ผู้ใช้มีอยู่แล้วแทน ส่วนที่ regex อ่านไม่ออกจะไป L4 เลย
> แผนเดิมคือให้ระบบเรียนรู้คำของผู้ใช้ลง `user_keyword_map` เพื่อให้ L3 จับได้เองครั้งหน้า

5. เริ่มรันยังไง
bash


npm install
cp .env.example .env        # ใส่ค่า LINE + Supabase
                            # แนะนำ: เริ่มด้วย AI_ENABLED=false ก่อน

# รัน supabase/migrations/001_init.sql แล้วตามด้วย 002_updated_at_trigger.sql, 003_budget_carry_over.sql และ 004_backfill_recurring_categories.sql
# ที่ Supabase > SQL Editor (โปรเจกต์นี้ไม่ได้ต่อ Postgres ตรงๆ จึงไม่มี DATABASE_URL)

npm run dev                 # เปิดที่ localhost:3000
ngrok http 3000             # เอา URL ไปใส่ใน LINE Developers Console
เช็คว่ารอด: เปิด /health ต้องได้ {"ok":true} แล้วทักบอทว่า กาแฟ 80

7. กฎการเขียนโค้ด
✅ ทำ

เงินทุกบาททุกสตางค์ผ่าน utils/money.ts (toSatang, add, formatBaht) เท่านั้น
ทุก query ต้องมี .eq('user_id', userId) — ไม่มีข้อยกเว้น
เรียก AI ผ่าน services/ai/router.ts ทางเดียว (ผ่าน checkAiAllowed() ใน guard.ts ก่อนเสมอ)
ผลของ AI ที่จะเขียน DB ต้องผ่าน createPending() → confirmPending() ใน pending.service.ts ทางเดียว
❌ ห้าม

parseFloat กับเงิน / คูณหาร 100 เอง
fetch ไป Gemini ตรงๆ ข้าม guard
เอา user_id มาจาก req.body หรือ req.query
เอา transfer ไปรวมในยอดสรุป
8. ก่อน Deploy ต้องผ่าน
 ตั้ง AI_ENABLED=false แล้ว npm test เขียวหมด ← ข้อสอบใหญ่สุด
 RLS เปิดครบทั้ง 12 ตาราง
 ลองยิง webhook ด้วยลายเซ็นผิด → ต้องได้ 401
 กดปุ่มยืนยันรัวๆ 5 ครั้ง → ต้องบันทึกแค่ครั้งเดียว
 0.1 + 0.2 ต้องได้ 0.30 ไม่ใช่ 0.30000000000000004
9. ติดปัญหาบ่อย

อาการ	สาเหตุที่พบบ่อย
บันทึกซ้ำ 2 รายการ	webhook_events ไม่ทำงาน หรือ LINE retry
AI ไม่ตอบ	เช็ค ai_usage_log — น่าจะโควตาเต็มหรือ timeout
ยอดเพี้ยนหลักสตางค์	มีใครใช้ float ที่ไหนสักที่ — หา parseFloat
กดยืนยันแล้วไม่บันทึก	pending หมดอายุ (24 ชั่วโมง — PENDING_EXPIRE_HOURS ใน config/constants.ts)
ยอดสรุปสูงผิดปกติ	transfer หลุดเข้าไปรวม (G7)
10. คำถามที่ทีมถามบ่อย
Q: ทำไมไม่ให้ AI คำนวณเลย มันก็คิดเลขได้นี่? A: LLM ทายคำถัดไป ไม่ได้คิดเลข พลาดครั้งเดียวกับเงินคนอื่น = จบ

Q: ทำไมต้องให้กดยืนยันทุกครั้ง น่ารำคาญ? A: กดเฉพาะตอนที่ AI เดา (L4) กับสลิปเท่านั้น พิมพ์ปกติ (L1–L3) บันทึกทันที ไม่ต้องกด

Q: ถ้า Gemini ล่มทั้งวันล่ะ? A: ผู้ใช้ยังจดเงิน ดูสรุป ตั้งงบ ดูแผนออมได้ครบ — แค่พิมพ์ให้ตรงรูปแบบขึ้นหน่อย นั่นคือ G4
