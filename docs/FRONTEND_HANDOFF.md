## 3. โครงสร้างแต่ละหน้า (ฟีเจอร์ที่มีอยู่จริง)

- **`index.html` ภาพรวม:** hero ดำ (ปุ่มมุมขวาบนเลือกช่วงเวลา วันนี้ / สัปดาห์นี้ / เดือนนี้ — ถ้าเปิดเพดานไว้จะโชว์แถบความคืบหน้า ใช้ไป/เพดาน ถ้ายังไม่เปิดจะโชว์มุมมองเดิม ใช้ได้วันนี้ / เงินที่เหลือเดือนนี้) + ปุ่มลัด 4 ปุ่ม (`[data-hero-action="add"]` เปิดฟอร์มเพิ่มรายการ ที่เหลือเป็นลิงก์) → งบประมาณรายเดือน (`#monthlyBudgetSummary`: แท็บรายจ่าย/รายรับ, เลือกเดือน, แท่งสัดส่วนหมวดพร้อม popover, ขยายดูรายหมวด, แถวหมวดกดแล้วเปิดรายละเอียด พร้อมปุ่มไปหน้าประวัติที่กรองหมวด+เดือนไว้) → `#dashboardPlans` → รายการล่าสุด
- **`transactions.html` ประวัติ:** การ์ดดำสรุปรายรับ/รายจ่ายของช่วงที่เลือก, ค้นหา, แท็บทั้งหมด/รายรับ/รายจ่าย, ชิปหมวดหมู่, ช่วงวันที่, เลือกหลายรายการ (แก้หมวด+ประเภทพร้อมกัน, ลบ), เพิ่ม/แก้/ลบรายการ, รับ deep link `?category=ID&month=YYYY-MM`
- **`categories.html` หมวดหมู่:** การ์ดดำรวมงบ (เฉพาะรายจ่าย/รายรับตามแท็บ) พร้อม popover แท่งสัดส่วน, แท็บกรอง+ค้นหา, เพิ่ม/ลบ/ตั้งงบ/สวิตช์ "หมวดจำเป็น", โหมดจัดเรียง, รายละเอียดหมวด (แท็บภาพรวม = โดนัท, แท็บประวัติ = แท่ง 6 เดือน + เส้นประงบ + ลิงก์ไปหน้าประวัติ)
- **`analyze.html` วิเคราะห์:** แท็บ ภาพรวม / รายหมวด
  - ภาพรวม: สรุปสถานะ, แนวโน้ม 6 เดือน (แท่งคู่ + แถวรายรับ/รายจ่ายกดดูรายละเอียด), ไทล์ "ใช้อย่างปลอดภัยได้" (อัตราใช้จ่าย, การคาดการณ์, กองทุนฉุกเฉิน — กดดูคำอธิบาย) + ป้ายความมั่นใจ (กดดูความหมาย), โดนัทสัดส่วนหมวดพร้อม popover, แผนเก็บเงิน (กดการ์ด = รายละเอียด, ⋮ = ดูรายละเอียด/ประวัติการเงิน/โอนเข้า/แก้ไข/ลบ, สร้างแผน 3 ขั้นตอน), จำลองผลกระทบก่อนซื้อ (+ หน้าอธิบายวิธีคิด)
  - รายหมวด: เลื่อนเดือน, ชิปเลือกหมวด, กราฟแท่งย้อนหลัง, ไทล์สถิติ 4 อัน (กดดูรายละเอียด), รายการแยกหมวด
- **`settings.html` ตั้งค่า:** โปรไฟล์จาก `/api/me`, **เพดานการใช้จ่าย** (รายวัน/สัปดาห์/เดือน เปิดปิดแยกกัน เลือกโหมดระบบคำนวณ/ตั้งเอง + ปุ่มเลือกรูปแบบประหยัด/ปานกลางของโหมดระบบคำนวณ — ดูหัวข้อ 7.6), สวิตช์ ผู้ช่วย AI (สะท้อน `aiEnabled` จาก API แบบอ่านอย่างเดียว) / สรุปรายวัน (ล็อกไว้ ยังไม่มี API), อีเมลสำหรับ forward + ปุ่มสร้าง token ใหม่ (เรียก API จริง) + จำนวนอีเมลที่อ่านยอดไม่ออก

## 4. Pattern/ตัวช่วยที่ใช้ซ้ำใน `app.js` (ใช้ตัวเดิมก่อนเขียนใหม่)

- **Modal:** `openModal(html)` / `closeModal()` / `showSuccessModal(text)`; ปุ่มปิดใช้ `data-close-modal`
- **Modal อธิบายรายละเอียด:** `openInsightModal({title, value, pill, progress, lead, rows, extra, tip, action, footer})` — ใช้กับไทล์, ผลจำลอง, รายละเอียดแผน, รายละเอียดแนวโน้ม ฯลฯ
- **Modal กรอกเงิน:** `openAmountInputModal(satang, onComplete, title)` (ช่องกรอกเป็นบาท คืนค่าเป็นสตางค์)
- **Popover แท่ง/โดนัท:** `showBarTip` / `hideBarTip` / `bindBarTip(ctx)` โดย ctx = `categoryOverviewTip`, `dashboardBudgetTip`, `analyzeDonutTip` (ส่วนต้องมี `data-overview-seg`; มือถือแตะเพื่อเปิด)
- **ฟอร์ม:** `renderCustomSelect`, `renderCustomDateField`, `renderCustomTimeField` + `bind…` (dropdown/ปฏิทิน/เวลา แบบ custom แทน native)
- **แผนเก็บเงิน:** `recalcPlanProgress`, `openPlanTransfer`, `openPlanDetail`, `openPlanMenu`, `openPlanHistory` (แก้ไข/ลบรายการโอนได้), `getEmergencyPlan`, `applyEmergencyType`
- **การเรนเดอร์หน้าวิเคราะห์:** `renderAnalyzePage()` เรนเดอร์อย่างเดียว เรียกซ้ำได้; ผูก event ครั้งเดียวที่ `bindAnalyzePage()` (ของที่วาดใหม่ใช้ event delegation) — ระวังผูก listener ซ้ำเวลาเพิ่มปุ่มใหม่

**ข้อควรระวังที่เคยเป็นบั๊ก**
- เงินใน mock เก็บเป็น **สตางค์ (×100)**; `formatMoney` หาร 100 ให้; ช่อง input เป็นบาทจริง ต้องคูณ 100 ก่อนเก็บ
- ~~CSS ที่ตั้ง `display` ทับ attribute `hidden`~~ → **แก้ที่เดียวจบแล้ว** ท้าย `style.css` มีกฎ `[hidden] { display: none !important; }` (โดนกับดักนี้มา 3 รอบก่อนจะยอมคุมรวม) — ไม่ต้องเขียน `X[hidden]` รายคลาสอีก
- ลูก flex/grid ต้องมี `min-width:0` กันหน้าล้นแนวนอน; popover ใน modal ที่ scroll ได้ต้องใช้ `position:fixed`
- ไฟล์ CSS/JS ในทุก HTML มี **`?v=20260920b`** กันแคช — **แก้ CSS/JS แล้วให้เปลี่ยนเลขนี้ทุกหน้า** (`sed -i 's/?v=OLD/?v=NEW/g' *.html`) ไม่งั้นผู้ใช้อาจเห็นไฟล์เก่า
- **id จาก API เป็น UUID ที่เป็นข้อความ** ห้ามใช้ `Number(id)` เทียบ ให้ใช้ `sameId(a, b)`
- **`type='transfer'` (โอนเข้าแผนออม) ปนมาใน `/api/transactions`** ห้ามนับรวมเป็นรายรับ/รายจ่าย (G7)
  ใช้ `isTransfer(item)` กรองก่อนบวกยอดเสมอ และแสดงผลเป็นสีกลาง (`.amount.transfer`) ไม่ใส่เครื่องหมายลบ
- `/api/transactions` มีรายการ `type: 'transfer'` (เงินโอนเข้าแผน) ปนมาด้วย ห้ามนับเป็นรายจ่าย (G7)
- ค่าที่ API ยังไม่มีให้ ส่งเป็น `null` ไม่ใช่ `0` — ระวัง `null < 7` ได้ `true` เวลาเช็คเงื่อนไข

## 6. วิธีทดสอบ (ที่ใช้มาตลอด)

- เสิร์ฟ `web/` ด้วย `python3 -m http.server 8123` แล้วขับด้วย Playwright (headless Chromium) — ติดตั้ง `playwright` ในโฟลเดอร์ชั่วคราวนอกโปรเจกต์ (browser cache อยู่ที่ `~/.cache/ms-playwright`) — วิธีนี้ทดสอบได้เฉพาะตอนยังใช้ mock พอต่อ API แล้วต้องรัน `npm run dev` แล้วเปิด `localhost:3000` แทน
- ตรวจอย่างน้อย: มือถือ 360/400px (แตะด้วย `hasTouch`), แท็บเล็ต 820px, เดสก์ท็อป 1280px, ไม่มี console error, ไม่มีหน้าล้นแนวนอน (`scrollWidth - innerWidth`)
- ระวัง `pkill -f` ที่ pattern ตรงกับคำสั่ง shell ตัวเอง (จบด้วย exit 144) — ปิด server ด้วยคำสั่งแยกต่างหาก

### 7.1 ต่อ API จริง — ✅ เสร็จแล้ว (2026-09-20)

ทำผ่าน `web/js/boot.js` ทำงานตามลำดับ: `GET /api/me` → 401 แสดงการ์ดเข้าสู่ระบบ (ไม่ redirect เอง)
→ ถ้าผ่าน ดึง `/api/summary`, `/api/budgets`, `/api/categories`, `/api/transactions`, `/api/plans`
พร้อมกัน แล้วแปลงเป็นรูปที่ `app.js` ใช้ (เขียนทับ `window.mockData` ในที่เดิม เพราะ `app.js`
จับ reference ไว้ตั้งแต่โหลด) แล้วสั่ง render ใหม่

การบันทึกข้อมูลไปผ่าน `window.jodtangPersist` ซึ่ง `app.js` เรียกแทนการแก้ข้อมูลในเครื่อง
ทุกครั้งที่เขียนสำเร็จจะโหลดข้อมูลใหม่ทั้งชุด เพื่อให้ยอดบนหน้าเป็นเลขที่ backend คำนวณ

| ทำได้แล้ว | endpoint |
|---|---|
| เพิ่ม/แก้/ลบรายการ | `POST` `PATCH` `DELETE /api/transactions` |
| ตั้งงบรายหมวด | `PUT /api/budgets/:categoryId` |
| ยกเลิกงบรายหมวด | `DELETE /api/budgets/:categoryId` |
| สร้างแผน (เลือกจาก 3 ทางเลือกที่ backend คำนวณ) | `POST /api/plans` → `/confirm` |
| โอนเข้าแผน / ยกเลิกแผน | `POST /plans/:id/transfer` · `DELETE /plans/:id` |
| สร้างที่อยู่อีเมลใหม่ | `POST /api/settings/email-token/rotate` |
| เปลี่ยนเดือนในวิดเจ็ตงบ | `GET /api/budgets?month=` (ดึงเมื่อกดเปลี่ยนเดือน) |
| รายการประจำ (ดู/เพิ่ม/ลบ) | `GET` `POST /api/recurring` · `DELETE /api/recurring/:id` |
| กำลังออมจริงในตัวช่วยสร้างแผน | `GET /api/plans/capacity` |

**เปิดหน้าเว็บได้ 2 แบบ**

| เปิดจาก | เกิดอะไรขึ้น |
|---|---|
| `npm run dev` แล้วเข้า `localhost:3000` | เรียก `/api/*` ได้ → ใช้ข้อมูลจริง (401 = ขึ้นการ์ดเข้าสู่ระบบ) |
| เซิร์ฟเวอร์ไฟล์ธรรมดา (Live Server, `python3 -m http.server`) | ไม่มี `/api/*` → เข้าโหมดตัวอย่าง: โชว์ mock พร้อมป้ายบอก และปุ่มทุกอย่างยังกดเล่นได้เหมือนก่อนต่อ API |

> โหมดตัวอย่างสำคัญตอนทำดีไซน์ — `boot.js` จะถอน `__jodtangApiWired` กับ `jodtangPersist`
> ออกแล้วเรียก `bindSettingsActions()` ใหม่ เพื่อคืนพฤติกรรมเดิมของ `app.js` ทั้งหมด
> **ถ้าแก้ boot.js อย่าลืมทดสอบทั้งสองแบบ**

**ข้อควรรู้เรื่อง id:** ข้อมูลตัวอย่างใช้ id เป็นตัวเลข แต่ API ใช้ UUID ที่เป็นข้อความ
`app.js` เดิมใช้ `Number(id)` ซึ่งทำให้ UUID กลายเป็น `NaN` แล้วหาอะไรไม่เจอเลย
ตอนนี้เปลี่ยนไปใช้ `sameId(a, b)` ที่เทียบแบบไม่สนชนิดแล้วทุกจุด — **อย่าเผลอใส่ `Number()` กลับเข้าไป**

### 7.3 ฟีเจอร์ใน UI ที่ยังไม่มี endpoint รองรับ

ต้องคุยกับทีม backend ว่าจะเพิ่ม endpoint หรือจะตัดฟีเจอร์ออก

| ฟีเจอร์ | สถานะ |
|---|---|
| เพิ่ม / ลบ / จัดเรียงหมวดหมู่ | มีแต่ `GET /api/categories` ไม่มี POST/PATCH/DELETE |
| สวิตช์ "หมวดจำเป็น" | `isEssential` อ่านได้ แต่ไม่มี endpoint แก้ |
| ประวัติการเงินของแผน (แก้ไข/ลบรายการโอน) | มีแต่ `POST /plans/:id/transfer` ไม่มี GET ประวัติ และไม่มีทางแก้/ลบรายการโอน |
| แก้ไขแผน | มีแค่ confirm / transfer / cancel ไม่มี PATCH |
| กองทุนฉุกเฉิน (`plan.type === 'emergency'`) | ไม่มีฟิลด์นี้ใน API |
| สวิตช์ "ผู้ช่วย AI" / "สรุปรายวัน" | `/api/settings` คืน `aiEnabled` แบบอ่านอย่างเดียว (ค่าระดับระบบ) ไม่มีสวิตช์รายผู้ใช้ |
| `unparsedCount` (อีเมลที่อ่านยอดไม่ออก) | API ส่งมาให้ แต่หน้าตั้งค่ายังไม่แสดง |

| ปุ่ม 7 จุดที่กดแล้วบอกว่าใช้ไม่ได้ | **ซ่อนทิ้งไปเลย** ด้วย `hideUnsupported()` + `MutationObserver` (เมนู ⋮ สร้าง DOM ใหม่ตลอด) — โหมดตัวอย่างยังโชว์ครบไว้สาธิตดีไซน์ |
| เพดานหายเงียบๆ เมื่อเปลี่ยนเครื่อง | เตือนไว้ในหน้าตั้งค่า (`.limit-storage-note`) จนกว่าจะมี `/api/limits` |
| ลบรายการแล้วเลิกทำไม่ได้ | modal หลังลบมีปุ่ม **"เลิกทำ"** เรียก `api.restoreTransaction()` (backend เป็น soft delete อยู่แล้ว) |
| ไม่มีปุ่มออกจากระบบ | `#logoutBtn` ท้ายหน้าตั้งค่า → ถามยืนยัน → `api.logout()` |
| แตะชิปหมวดแล้วยอดสรุปกลายเป็น `—` เฉยๆ | `showRangeSummaryNote()` อธิบายว่าทำไมหาย และย้ำว่ารายการด้านล่างยังกรองถูก |

**ยังเหลือให้ backend ทำ:** endpoint สรุปยอดตามช่วง/หมวด, `/api/limits`, CRUD หมวดหมู่, แก้ไขแผน, ประวัติการโอนเข้าแผน, สวิตช์ตั้งค่ารายผู้ใช้ — พอมีแล้วให้เอา selector ที่เกี่ยวข้องออกจาก `UNSUPPORTED_SELECTORS` ใน `boot.js`

## 10. รวมตัวต่อ API สองชุด (2026-09-23)

ระหว่างที่ฝั่งนี้ทำ `boot.js` อยู่ มีอีกคนหยิบ UI ชุดเดียวกันไปต่อ API ของตัวเองแล้วขึ้น main
(`3eca7d3 Integrate the new frontend UI`) กลายเป็น `boot.js` สองชุดที่ไม่มีฝั่งไหนครอบอีกฝั่งได้หมด
รอบนี้รวมเป็นชุดเดียวแล้ว วิธีตัดสินและผลลัพธ์:

**ไฟล์ UI (`css/style.css`, `*.html`, `js/app.js`)** — เทียบกับฐานเดียวกันแล้วต่างกันแค่ 31 บรรทัด
`style.css` เหมือนกันเป๊ะ ส่วนที่ต่างคือ `Number(id)` → `String(id)` ซึ่งฝั่งนี้แก้ไปแล้วด้วย `sameId()`
(30 จุด เทียบกับ 11 จุด) จึงใช้ของฝั่งนี้ทั้งหมด ไม่มีอะไรตกหล่น

**`js/boot.js`** — คนละสถาปัตยกรรมกัน จึงเลือกโครงเดียวแล้วย้ายฟีเจอร์ข้ามมา

| | ชุดที่ขึ้น main ไปก่อน | ชุดนี้ (ที่เก็บไว้) |
|---|---|---|
| วิธีต่อ | ทับ `window.*` ของ `app.js` แล้วสร้าง HTML เอง | แปลงข้อมูลลง `window.mockData` ให้ `app.js` วาดตามปกติ + เขียนผ่าน `window.jodtangPersist` |
| ผลเมื่อ UI เปลี่ยนหน้าตา | การ์ดแผนที่สร้างเองจะกลายเป็นมาร์กอัปเก่าที่ CSS ใหม่ไม่รองรับ | ไม่กระทบ เพราะไม่ได้สร้าง HTML ของหน้าเอง |
| ลบงบรายหมวด / รายการประจำ / กำลังออมจริง | ✅ | ย้ายมาแล้วรอบนี้ |
| เพิ่ม/แก้/ลบรายการเงิน + เลิกทำ | ❌ | ✅ |
| เพดานการใช้จ่าย (§7.6) | ❌ | ✅ |
| โหมดตัวอย่าง / จอออฟไลน์ / จอยังไม่ล็อกอิน แยกจากกัน | ❌ | ✅ |

ที่ต้องรู้ตอนอ่านโค้ดเก่าเทียบ (ดูได้ที่ `git show 3eca7d3:web/js/boot.js`):

- **"กรอกงบ 0 = ยกเลิกงบ" ใช้ไม่ได้จริง** — `openAmountInputModal` ตีกลับค่า 0 ตั้งแต่แรก
  (`if (!(amount > 0)) return;`) `deleteBudget` ฝั่งนั้นจึงไม่เคยถูกเรียก รอบนี้ทำเป็นปุ่ม
  **"ยกเลิกงบ"** ในเมนูหมวด โผล่เฉพาะหมวดที่ตั้งงบไว้
- **บั๊ก `initializePage()` ถูกเรียกสองรอบ** ที่ฝั่งนั้นเจอและกันไว้ด้วย `transactionControlsBound`
  ไม่เกิดกับโครงนี้ เพราะ `boot.js` ชุดนี้เรียกแค่ฟังก์ชันวาดหน้า (`renderCurrentPage()`)
  ไม่ได้เรียก `initializePage()` ซ้ำ — **อย่าเผลอเปลี่ยนไปเรียก `initializePage()` ทีหลัง**
  ไม่งั้น listener ระดับ document จะถูกผูกสองชุด กดครั้งเดียวทำงานสองครั้ง
