- ⚖️ **G5** — ลบข้อมูลส่วนบุคคลออกก่อนส่งให้ AI และไม่ส่งยอดเงินคงเหลือเข้า prompt (`src/utils/redact.ts` · `tests/redact.test.ts`)

## 2. อะไรเวิร์ค

| เรื่อง | ตัวอย่างจริงในโปรเจกต์ |
|---|---|
| **งานที่มีแบบแผนชัดเจน** | เขียน query ที่ต้องกรอง `user_id` ทุกครั้ง (⚖️ G6) · แปลงรูปข้อมูลระหว่างชั้น · เขียนเทสต์ตาม acceptance criteria ที่ทีมกำหนดไว้แล้ว |

## 3. อะไรไม่เวิร์ค — ต้องแก้เอง

> ทุกข้อด้านล่างเป็นเหตุการณ์ที่เกิดขึ้นจริง ไม่ใช่ข้อควรระวังทั่วไป

### 3.1 โค้ดที่ "ดูถูก" แต่ผิดเรื่องเงิน

AI เขียนการเทียบเกณฑ์เตือนงบโดยใช้เปอร์เซ็นต์ที่ปัดแล้ว อ่านผ่าน ๆ ดูไม่ออกเลยว่าผิด
แต่ **79.99966% จะถูกปัดเป็น 80.0** แล้วยิงเตือนเร็วไปหนึ่งครั้ง ซึ่ง**เผาสิทธิ์เตือนของทั้งเดือนทิ้ง**
เพราะระบบออกแบบให้เตือนแต่ละเกณฑ์ได้ครั้งเดียวต่อเดือน

**แก้โดย** เปลี่ยนไปเทียบด้วยการคูณไขว้จำนวนเต็ม และเขียนเทสต์ล็อกค่าขอบนี้ไว้โดยเฉพาะ
(`tests/budget.service.test.ts`)

### 3.2 เทสต์เขียวทั้งที่ไฟล์ไม่ได้ถูกรัน — เกิด 2 ครั้ง

เทสต์บางไฟล์ import พัง Vitest ข้ามไฟล์นั้นเงียบ ๆ แล้วยังรายงานว่า "passed"
จำนวนเทสต์ลดลงโดยไม่มีใครสังเกต **แก้โดย** เพิ่ม `tests/setup.ts` แก้ที่ต้นเหตุ
และนับจำนวนเทสต์ทุกครั้งที่รัน ไม่ดูแค่คำว่า passed

### 3.3 AI เดาสาเหตุผิดแล้วพูดอย่างมั่นใจ

ครั้งหนึ่งสรุปว่ารายการหายเพราะ `user_id` ไม่ตรง พอไปเช็ค API จริงพบว่าข้อมูลอยู่ครบ
สมมติฐานผิดทั้งหมด — **บทเรียนคือคำอธิบายที่ฟังขึ้นไม่เท่ากับคำอธิบายที่ถูก**

### 3.4 AI ไม่รู้พฤติกรรมจริงของบริการภายนอก

- **Gmail ตัด `+token` ออกจาก header `Delivered-To`** ตอน forward ทำให้ระบบหาเจ้าของอีเมลไม่เจอ
  AI เดาว่า token หาย แต่เดาถูกด้วยเหตุผลผิด — ความจริงคือ Gmail ตัดจาก header หนึ่งแต่เก็บไว้ในอีกหนึ่ง
  รู้ได้ก็ต่อเมื่อยิงอีเมลจริงแล้วอ่าน log · ยืนยันด้วยการโอนเงินจริง 131 บาท
- **Gemini รุ่นที่ตั้งเป็นค่าเริ่มต้นถูกปิดไปแล้ว** ต้องเปลี่ยนไปรุ่นที่ยังมีอยู่ ไม่มีทางรู้จากโค้ด

### 3.5 เครื่องมือจำลองไม่เท่ากับเครื่องจริง

ตอนทำการ์ด Flex ทดสอบใน **LINE Flex Message Simulator** บนเดสก์ท็อปผ่านหมด
แต่พอส่งเข้ามือถือจริงพบว่าพัง **3 จุด** ที่ Simulator วาดให้เห็นปกติ

| อาการบนมือถือ | สาเหตุ |
|---|---|
| แถบความคืบหน้าหายทั้งแถบ | กล่องด้านในไม่ได้กำหนดความสูงของตัวเอง เลยสูง 0 |
| ป้ายหมวดกลายเป็นวงกลมดำ ไม่มีตัวหนังสือ | ใช้ `layout: baseline` แล้วกล่องยุบจนความมนกินทั้งกล่อง |
| ปุ่มแก้ไข/ลบหายไปเลย | ห่อไอคอนไว้ในกล่องซ้อนที่ `flex: 0` แล้วยุบ |

**แก้โดย** ส่งการ์ดเข้ามือถือจริงทุกครั้งก่อนเขียนเป็นโค้ด และเขียนเทสต์ล็อกทั้งสามข้อไว้
(`tests/flexCards.test.ts`) เพื่อไม่ให้ใครแก้กลับโดยไม่รู้ตัว

### 3.6 เอกสารที่ AI ช่วยเรียบเรียงมีตัวเลขคลาดเคลื่อน

ตรวจ SRS ที่ส่ง M2 เทียบกับโค้ดจริงแล้วพบ 3 จุด: บอกว่าหมวดตั้งต้นมี 12 หมวด (จริง 11) ·
บอกว่ามี 23 endpoint (จริง 26) · บอกว่าโควตา push คือ 280 ข้อความ **ต่อผู้ใช้**
ทั้งที่โค้ดนับ **ต่อช่องทางทั้งระบบ** — ข้อหลังสำคัญเพราะถ้าทำตามเอกสารจะทะลุ free tier ทันที

**บทเรียนคือ ตัวเลขทุกตัวในเอกสารต้องไล่เช็คกับโค้ด ไม่ใช่เชื่อฉบับร่าง**

### 3.7 ต้องป้อนบริบทเองทุกครั้ง

ถ้าไม่ชี้ไปที่ `SPEC.md` กับ `AIDO.md` AI จะเสนอวิธีที่ขัดกฎเหล็ก เช่น ให้ AI คำนวณยอดเงินเอง
ซึ่งผิด G1 ตั้งแต่บรรทัดแรก

## 4. บทเรียน

1. **กฎต้องเป็นเอกสาร ไม่ใช่คำเตือนเป็นครั้ง ๆ** — `AIDO.md` กับกฎเหล็ก 7 ข้อทำให้ไม่ต้องย้ำเรื่องเดิมซ้ำทุกครั้ง และคนในทีมก็ใช้อ้างอิงกันเองได้

2. **AI เร่งการเขียนโค้ดได้ แต่ไม่ได้เร่งการ "รู้ว่าถูก"** — สิ่งที่ทำให้กล้าแก้โค้ดคือเทสต์ **766 ข้อ** ไม่ใช่ความมั่นใจของ AI

3. **แยกส่วนที่ AI ห้ามแตะออกมาเป็นโมดูลจริง ๆ** — การออกแบบให้ Money Engine ไม่รู้จัก AI เลย ทำให้กฎบังคับใช้ได้ด้วยโครงสร้าง ไม่ต้องอาศัยว่าใครจะจำได้

4. **ทดสอบกับของจริงเสมอ** — บั๊ก `+token` ของ Gmail และบั๊กการ์ด Flex ทั้ง 3 ข้อ ไม่มีทางเจอจาก unit test หรือเครื่องมือจำลอง เพราะปัญหาอยู่ที่พฤติกรรมของระบบภายนอก

5. **ให้ AI ร่างได้ แต่ตัวเลขต้องไล่เช็คเอง** — ทั้งในโค้ดและในเอกสาร จุดที่ AI พลาดบ่อยที่สุดคือค่าคงที่และเงื่อนไขขอบ ซึ่งเป็นจุดเดียวกับที่เสียหายหนักที่สุดเมื่อผิด
