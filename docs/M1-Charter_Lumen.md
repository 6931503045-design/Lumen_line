## 1. ปัญหา

**ใคร:** นักศึกษามหาวิทยาลัยอายุ 18–24 ปี ที่มีเงินใช้จำกัดในแต่ละเดือน

**เจ็บปวดอะไร:**

1. **จดแล้วเลิก** — แอปจดรายจ่ายทั่วไปต้องทำหลายขั้น (เปิดแอป → เลือกหมวด → พิมพ์ยอด → บันทึก) ผู้ใช้ส่วนใหญ่เลิกจดภายใน 2–3 สัปดาห์
2. **รู้แค่ว่าเงินหายไปไหน แต่ไม่รู้ว่าต้องทำอะไรต่อ** — แอปบอกได้ว่าเดือนนี้ใช้ไปเท่าไหร่ แต่ไม่ตอบคำถามที่ผู้ใช้อยากรู้จริง ๆ

ทั้งโปรเจกต์มีอยู่เพื่อตอบ **2 คำถาม**:

> **คำถามที่ 1** — "วันนี้ฉันใช้เงินได้อีกเท่าไหร่?"\
> **คำถามที่ 2** — "อยากได้สิ่งนี้ ต้องออมเดือนละเท่าไหร่ถึงจะไหว?"

ฟีเจอร์ไหนไม่โยงกลับไปหาคำถามใดคำถามหนึ่ง ถือว่าอยู่นอกขอบเขต

## 2. ผู้ใช้เป้าหมาย

| ลักษณะ | รายละเอียด |
|---|---|
| รายได้ | เงินจากผู้ปกครองเป็นก้อนต่อเดือน + งานพาร์ทไทม์บ้าง |
| พฤติกรรม | ใช้ LINE ทุกวัน · จ่ายเงินผ่านแอปธนาคาร (K PLUS) · ไม่เปิดแอปการเงินแยก |
| ความเจ็บปวด | สิ้นเดือนเงินหมดโดยไม่รู้ว่าหมดไปกับอะไร · อยากได้ของแต่ไม่รู้ว่าเก็บไหวไหม |
| ทำไมต้องเป็น LINE | ผู้ใช้อยู่ใน LINE อยู่แล้ว — พิมพ์ `กาแฟ 80` จดได้ใน 1 ข้อความ ไม่ต้องเปิดแอปใหม่ |

**ผู้มีส่วนได้ส่วนเสียอื่น:** ทีมพัฒนา 5 คน · อาจารย์ผู้สอน · ผู้ให้บริการภายนอก (LINE, Supabase, Google Gemini, Render)

## 3. ขอบเขต

### ✅ ทำ (In scope)

- บันทึกรายรับ/รายจ่ายผ่าน **แชท LINE** และ **อีเมลแจ้งเตือนของธนาคาร** (K PLUS)
- คำนวณ **เงินที่ใช้ได้ต่อวัน** จากพฤติกรรมจริง → ตอบคำถามที่ 1
- **งบรายหมวด** พร้อมเตือนเมื่อใช้ถึง 80% และ 100%
- **แผนออม** เสนอ 3 ทางเลือก + ติดตามความคืบหน้า → ตอบคำถามที่ 2
- **หน้าเว็บ 5 หน้า** ใน LINE (LIFF) สำหรับดูกราฟและจัดการข้อมูล
- สกุลเงิน **บาทเท่านั้น**

### ❌ ไม่ทำ (Out of scope)

| ไม่ทำ | เหตุผล |
|---|---|
| เชื่อม API ธนาคาร / Open Banking | ต้องขออนุญาตระดับสถาบัน เกินขอบเขตวิชา |
| ติดตามการลงทุน หุ้น คริปโต | ไม่ตอบ 2 คำถามหลัก |
| หลายสกุลเงิน | ผู้ใช้เป้าหมายใช้บาทอย่างเดียว |
| เก็บเงินผู้ใช้ / เชิงพาณิชย์ | เป็นโปรเจกต์การศึกษา งบ 0 บาท ใช้ free tier ทั้งหมด |
| แอป native / เว็บแอปแยก | ใช้ LIFF ใน LINE แทน ลดขั้นตอนการเข้าใช้ |
| AI คำนวณเงินหรือพยากรณ์ตัวเลข | กฎเหล็ก G1 — ตัวเลขเงินทุกบาทมาจากโค้ด ไม่ใช่ AI |
| แชทคุยเล่นทั่วไป | AI ตอบได้เฉพาะคำถามกลับเพื่อความชัดเจน |
| พยากรณ์เชิงสถิติขั้นสูง (Monte Carlo) | เกินความจำเป็นของ MVP |

## 5. กระบวนการพัฒนา (SDLC)

**เลือก: Incremental** — ส่งมอบเป็นรอบละ 1 สัปดาห์ แต่ละรอบได้ระบบที่ใช้งานได้จริงเพิ่มขึ้นทีละชั้น

| รอบ | เป้าหมาย | เสร็จเมื่อ |
|---|---|---|
| W1 | ฐาน + ทางด่วน | พิมพ์ `กาแฟ 80` แล้วลงฐานข้อมูลจริง · webhook ตรวจลายเซ็น · เทสต์ money ผ่าน |
| W2 | สรุปและเงินที่ใช้ได้ | คำสั่ง `สรุป`, `เหลือ` · รายการประจำ · โควตา push |
| W3 | ฟีเจอร์เด่น | แผนออม · งบรายหมวด · หน้าเว็บ 5 หน้า |
| W4 | ครบวงจร + ทดสอบ | อีเมลธนาคาร + กันนับซ้ำ · เทสต์ครบ · ทดสอบ `AI_ENABLED=false` ทั้งแอป |

**เหตุผลที่เลือก:**

1. **มีของที่ใช้ได้ตั้งแต่สัปดาห์แรก** — ถ้าเวลาหมดกลางทาง ยังมีระบบจดเงินที่ทำงานได้ส่ง ไม่ใช่ของครึ่ง ๆ กลาง ๆ
2. **ตัดฟีเจอร์ได้ตามลำดับความสำคัญ** — ถ้าล่าช้า ตัด Could ก่อน แล้วค่อย Should · ห้ามตัด Must, เทสต์ของ Money Engine และความปลอดภัย
3. **ลดความเสี่ยงจาก AI** — มีด่านบังคับว่าห้ามต่อ Gemini จนกว่าทางด่วน (regex) ของ W1 จะผ่าน ระบบจึงไม่พึ่ง AI (G4)
4. **เหมาะกับทีมประสบการณ์น้อย** — งานแต่ละรอบเล็กพอให้ทดสอบและแก้ได้ทันก่อนรอบถัดไป
